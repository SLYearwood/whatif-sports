# whatif-sports

An automated pipeline for a faceless sports "What If" channel. It turns an idea into a vertical Short (9:16, under 60s) and posts it to YouTube Shorts, TikTok and Instagram Reels.

Owner: Shawn (GitHub: SLYearwood). Python project, developed with Claude Code.

## Goal

Automate about 90% of production. A human approves every idea and every script before anything is published. That review step is mandatory, not optional. It keeps the channel within YouTube's "inauthentic content" monetization rules, which demonetize generic, repetitive and template-based mass-produced content. Each video needs a real take: an argued alternate outcome built on real stats, not a generic summary.

## Content rules (hard constraints)

- **No game footage or broadcast clips, ever.** League footage triggers Content ID and copyright strikes. Every visual is generated by our own code.
- **No team logos or league marks.** Use team names, city names, colors and stats only.
- **No realistic AI depictions of real athletes.** Use stylized or abstract graphics (silhouettes, X/O play diagrams, stat cards, typography).
- Facts in the "what really happened" part must be accurate. Every script stores its stat sources in its YAML so they can be checked.
- If any AI-generated realistic imagery is ever added, set the platform's AI or synthetic-content disclosure flag on upload.

## Pipeline

```
ideas → (human approve) → script → (human approve) → voice → visuals → assemble → publish
```

```
whatif_sports/
├── ideas/        # pull sports news/trends, have an LLM pitch "what if" angles, score them, write to queue
├── script/       # LLM drafts a script YAML from an approved idea (real stats + sources)
├── voice/        # TTS per segment (ElevenLabs API; ffmpeg `flite` as an offline fallback for dev)
├── visuals/      # Pillow-rendered frames: title card, stat card, scoreboard, play diagram, timeline
├── assemble/     # segment clips + audio + burned-in captions → final MP4 via ffmpeg
├── publish/      # YouTube Data API, TikTok Content Posting API, Instagram Graph API + scheduler
├── review/       # simple local web UI (FastAPI or Flask) to approve/edit ideas and scripts
├── store/        # SQLite: ideas, scripts, renders, posts, status, metrics
└── cli.py        # `whatif idea`, `whatif script <id>`, `whatif render <id>`, `whatif publish <id>`
data/             # queue, renders, audio cache (gitignored)
tests/
```

Status flow for an item: `idea_pending → idea_approved → script_draft → script_approved → rendered → scheduled → posted` (or `rejected`).

## Script format (the contract between modules)

```yaml
id: seahawks-xlix-run
title: "What if the Seahawks just ran it?"
sport: nfl
hook: "One yard. Marshawn Lynch. And they threw it."
sources:
  - "Super Bowl XLIX box score, Feb 1, 2015"
segments:
  - type: title          # visual template
    text: "What if the Seahawks just ran it?"
    narration: "Super Bowl 49. Second and goal from the one. Seattle has Marshawn Lynch... and they throw it."
  - type: stat
    big: "1 yd"
    label: "Ball on the Patriots' 1-yard line, 26 seconds left"
    narration: "..."
  - type: play_diagram
    play: inside_zone    # named play from visuals/plays.py
    narration: "..."
  - type: timeline
    events:
      - year: 2015
        text: "Seattle wins back-to-back titles"
      - year: 2016
        text: "..."
    narration: "..."
  - type: outro
    text: "Was it the worst call ever? Comment below."
    narration: "..."
```

Each segment's length = its narration audio length plus a small pad. Captions come from the narration text, timed proportionally across the audio (switch to Whisper word timestamps later if needed).

## Video style

- 1080x1920, 30fps, H.264 + AAC, under 60s (aim for 35–50s).
- Bold type (Inter Black or similar), high contrast, 2–3 brand colors plus team colors for accents.
- Subtle motion on every frame (slow zoom/pan, counters ticking up, timeline items sliding in) so nothing is static.
- Big centered captions, max ~4 words on screen at a time, kept out of the bottom ~20% (platform UI covers it).
- The hook line goes in the first 2 seconds.

## Milestones

1. **Render one Short from a hand-written script YAML.** Visual templates + TTS + captions + ffmpeg assembly. Build this first. Use `flite` TTS so it works with no API key.
2. ElevenLabs voice (ideally a clone of Shawn's voice) with audio caching keyed by text hash.
3. Script generation: LLM (Anthropic API) drafts a script YAML from an idea; validate it against a schema (pydantic).
4. Review UI: list pending ideas and scripts; approve, edit or reject; preview the rendered MP4.
5. Idea generation: sports news/RSS + results feeds → LLM pitches → dedupe against past topics → queue. Mix evergreen topics with timely ones ("what if last night's kick went in").
6. Publishing: YouTube first (Data API `videos.insert`), then TikTok and Instagram. Respect quotas. Scheduled posting via cron or a simple scheduler. Note: API projects that haven't been audited are typically limited to private uploads on YouTube and TikTok, so apply for audits early and post manually until approved.
7. Metrics: pull views/retention per post into SQLite to see which topics and hooks work.

## Engineering conventions

- Python 3.11+, type hints, `ruff` for linting/formatting, `pytest` for tests.
- Secrets live only in `.env` (gitignored): `ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, YouTube OAuth client JSON path, TikTok/Instagram tokens. Never commit or print them.
- ffmpeg is called via `subprocess` with argument lists (no shell strings).
- Every stage is idempotent and re-runnable on a single item id; outputs are cached under `data/<id>/`.
- Nothing publishes unless the item's status is `script_approved` and a human triggered or scheduled it.
